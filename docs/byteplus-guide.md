# BytePlus ModelArk in SimpleNode

This guide explains how to generate Seedance 2.5 videos of an **AI-created character whose face is visible**, through BytePlus ModelArk, ByteDance's official platform.

BytePlus is **optional**. Without a BytePlus key, SimpleNode works as before, with fal.ai.

## Why BytePlus

Seedance 2.0 and 2.5 refuse any start or reference image that shows a realistic human face, even when that face was generated by AI. fal.ai then shows: *"The images or videos provided may contain likenesses of real people…"*. The rule comes from ByteDance and applies at every reseller. fal offers no way around it.

BytePlus ModelArk offers two authorized ways, which SimpleNode uses:

- **AI Portrait (way A)**: you upload the character's image to your private library of virtual portraits. BytePlus reviews it, then makes it usable in Seedance.
- **Trusted Seedream image (way B)**: an image with a face generated by Seedream 5.0 (text-to-image) on your BytePlus account is accepted by Seedance for 30 days.

SimpleNode uses no technique to trick the filter, and never will.

## What you pay

Every user brings **their own BytePlus account and keys**. No key comes with the app. All BytePlus generations are billed to your account, at BytePlus prices, within your quotas.

## Setup (once)

All these steps happen in the BytePlus console. SimpleNode doesn't automate them.

### 1. Account and Seedance 2.5 activation

1. Create an account at <https://console.byteplus.com/auth/signup> and get it verified (individual or company, as BytePlus requires).
2. Activating Seedance 2.5 requires **one** of these: a balance of at least $30 ([top up](https://console.byteplus.com/finance/overview)), an AI Savings Plan of at least $30, or a Seedance resource pack.
3. Activate the models in ModelArk: **Model activation** (Seedance 2.5, Seedream 5.0).

### 2. API key (Seedance and Seedream)

1. Open ModelArk → **API keys**: <https://ai.byteplus.com/ark/region:ap-southeast-1/apiKey>.
2. Create a key. The page shows two values:
   - **API Key**: this is the one to copy;
   - **Resource ID**: the key's id in the console. SimpleNode doesn't need it.

Creating an API key also creates an **IAM user**, for example `simplenode-xxxxx`, visible in IAM → **User**. It will be used in step 3.

### 3. Access Key and Secret Key (portraits only)

The portrait library doesn't accept the API key: it requires an **Access Key / Secret Key** pair (AK/SK). Without it, Seedance and Seedream still work; only the AI Portrait node needs it.

**Recommended method**: keys that can only reach portraits.

1. BytePlus console → **IAM** → **Permission policy** → **Create policy**. Name it for example `simplenode-portraits`, switch to the **JSON** editor, paste this block (taken from the BytePlus documentation) and confirm:
   ```json
   {
     "Statement": [
       { "Effect": "Allow", "Action": ["ark:*Asset*"], "Resource": ["*"] }
     ]
   }
   ```
2. IAM → **User**: on the row of the user created in step 2 (`simplenode-xxxxx`), click **Authorize** and choose the `simplenode-portraits` policy. For the scope, choose **all projects** (global), or at least the **default** project: that's where SimpleNode stores portraits.
3. Click this user's name, open the access keys tab and choose **Create access key**.
4. Copy the **Access Key ID** (it often starts with `AKLT`) and the **Secret Access Key**. The Secret is shown **only once**.

**Quick method**: IAM → **Access key management** → **Create access key**. Those keys have **full rights** on your BytePlus account. Prefer the recommended method.

### 4. Advanced Creation Rights (portraits only)

1. Activate the **Advanced Creation Rights**: [purchase guide](https://ai.byteplus.com/ark/region:ap-southeast-1/docs/seedance-2-0-purchase-guide).
2. When the **first portrait group is created**, BytePlus asks you to sign an **authorization letter** in the console. If an AI Portrait fails with an authorization message, open [My portraits](https://ai.byteplus.com/ark/region:ap-southeast-1/experience/gen_video?model=dreamina-seedance-2-0-260128) (My assets → Virtual Portrait), sign, then run the node again.

### 5. In SimpleNode

1. **Settings → BytePlus ModelArk**.
2. Paste the API key in **API key**, the Access Key in **Access Key (AK)**, the Secret in **Secret Key (SK)**, and click **Save** for each one.
3. Click **Test connection**. The test checks the API key and, when they are saved, the Access Key and Secret Key. When everything is ready, two green lines show:
   - "API key (Seedance, Seedream): connected."
   - "Access Key / Secret Key (portraits): connected."

   If the second line shows "User is not authorized to perform: ark:ListAssetGroups", the step 3 policy isn't attached to the IAM user, or not for the "default" project. Attach it, wait a minute, then test again.

The test generates nothing and costs nothing: it only reads the list of your tasks and portrait groups.

Region: `ap-southeast-1` (Johor), the only one described in the BytePlus documentation.

The keys are saved on your computer in `keys.json`, the app's private file, next to the fal key. They never go into projects or logs.

## The three nodes

They're in the library: **AI Portrait (BytePlus)** and **Seedream (BytePlus)** under Image, **Seedance 2.5 (BytePlus)** under Video. The first time a BytePlus node runs, the app reminds you that billing goes through your BytePlus account.

### AI Portrait (BytePlus)

- **Input**: the character's image. **Settings**: name (e.g. "Nora") and group ("SimpleNode" by default; created if missing).
- **Run** uploads the image and follows the review: **In review**, **Validated** or **Refused**. Once validated, the **Portrait** output holds the `asset://…` id.
- Running a portrait that's already validated doesn't upload the image again. If the review takes more than 20 minutes, run the node again later: it resumes following it.
- The image must show an **AI character that resembles no real person**, with no logo or brand: jpeg, png or webp, sides of 300 to 6000 px, under 30 MB. You alone are responsible for that.
- BytePlus doesn't publish why a portrait is refused. The node then reminds these conditions.
- BytePlus only accepts an image that is online: the image first goes through **fal storage**. So the fal key must be set too.
- BytePlus's advice for faithful faces: a front-facing portrait, neutral expression, above the shoulders, the face filling about two thirds of the image. You can add a vertical full-body image to the same group.

### Seedance 2.5 (BytePlus)

**Inputs**: Prompt, Portraits, Reference images, Start image, End image.

Seedance 2.5 has **two modes, which can't be mixed** in one generation:

| Mode | Inputs | What for |
|---|---|---|
| References | Portraits and/or Reference images (30 at most) | Keeping the character: this is the mode to use with an AI Portrait |
| Start / end | Start image, and optionally End image | Forcing exactly the first (and last) shot |

If both are connected, the node says so and doesn't launch. To keep Nora, connect her portrait and **describe the first shot in the prompt**.

In References mode, the prompt refers to the images by number: **"Image 1", "Image 2"…**, portraits first, then reference images, in the order they're connected. Example: *"The woman in Image 1 walks on a beach at sunset, medium shot, the camera following her."* Never write the `asset://` id in the prompt.

A face in the **start image** is only accepted if it comes from a Seedream (BytePlus) node in text-to-image, under 30 days old.

**Settings**:

- **Duration**: 4 to 30 s, or Auto.
- **Aspect ratio**: Adaptive, 16:9, 9:16, 1:1, 4:3, 3:4 or 21:9. It is forced to Adaptive with a start image.
- **Sound**: on or off.
- **480p draft**: on by default.
- **Resolution**: 480p, 720p or 1080p, without a draft only.

**Draft**: the node renders a 480p video labeled "480p draft", with its expiry date. If you like it, **Finalize in 1080p** renders the same video in 1080p, after you confirm the price. The draft can be finalized for **14 days**, and only with the BytePlus account that generated it.

The **Stop** button cancels a task still in the queue. A task already rendering can't be cancelled at BytePlus: it runs to the end and is billed.

### Seedream (BytePlus)

- **Inputs**: Prompt and up to 10 reference images. **Settings**: model (pro or flash) and size (2K or 1K).
- Without a reference image, the output is labeled **"Trusted for Seedance"** with its expiry date (30 days). You can connect it as the start image or a reference image of a Seedance 2.5 (BytePlus), even with a face.
- With reference images, trust isn't guaranteed: BytePlus only promises it for text-to-image.
- Don't edit a trusted image (crop, compression…): BytePlus only accepts the original output.

## Example recipe: a video of Nora

1. **Seedream (BytePlus)**, text-to-image: a portrait of Nora, a woman in her fifties, photorealistic, front-facing, neutral background. Or import an image of Nora already created by AI.
2. **AI Portrait (BytePlus)**: connect the image, name the portrait "Nora", run and wait for **Validated**.
3. **Seedance 2.5 (BytePlus)**: connect the portrait to **Portraits** and write the prompt ("The woman in Image 1…"). Keep the draft on, choose 5 s, then run.
4. If you like the draft: **Finalize in 1080p**.

The validated portrait is reused in every following video, with no new upload.

## With Claude Code (MCP)

- `list_node_types` lists the three nodes, their settings and how to use them.
- `estimate_cost` and `run` count their cost against the session cap.
- `finalize_draft` also finalizes BytePlus drafts.
- `portrait_status` gives the review status of an AI Portrait and its `asset://`.
- A request refused **before** generating (missing key, invalid input, refusal by the provider on submission), at fal or BytePlus, gives its amount back to the session cap.

## Common error messages

| Message | What to do |
|---|---|
| Add your BytePlus key in Settings | Steps 2 and 5 |
| BytePlus portraits require an Access Key and a Secret Key | Steps 3 and 5 |
| API key refused (invalid or revoked) | Create the key again in ModelArk → API keys |
| Access Key or Secret Key refused | Check both values; a lost Secret is replaced by a new key pair |
| Access denied (model not activated…) | Activate the model (step 1), or attach the policy to the IAM user (step 3) |
| User is not authorized to perform: ark:… | The IAM user doesn't have the policy: step 3, point 2. Check that it covers the "default" project or all projects |
| … sign the authorization letter… | Step 4 |
| Image refused by the face filter | Use a validated AI Portrait, or a Seedream (BytePlus) text-to-image output under 30 days old |
| Seedance 2.5 can't mix a start/end image with references | Disconnect one of them (see the two modes above) |
| Quota or request limit (QPM) exceeded | Wait a moment, then run again |
| Draft expired or not found | Over 14 days, or a draft from another account: run the draft again |
| Timed out | BytePlus didn't finish within an hour: run again |
